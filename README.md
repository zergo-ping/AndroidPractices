# AndroidPractices

Учебное приложение: каталог персонажей Rick and Morty, поиск, фильтры, избранное и профиль.

## Практика 6 — Профиль

Задание: https://github.com/AndroidUrfuAutumn2025/ConsecutivePracticesReadme/blob/main/Practice6.md

В нижней навигации появилась вкладка «Профиль». Карандаш открывает редактор ФИО,
аватарки и ссылки на резюме. «Готово» сохраняет профиль и возвращает к просмотру;
выход назад отменяет изменения полей. Нажатие на аватарку предлагает галерею или камеру.
«Резюме» скачивает файл и открывает внешний просмотрщик. Нужна прямая HTTPS-ссылка
на документ, например PDF, а не страница сайта с кнопкой скачивания.

### Архитектура и хранение

- `domain`: модель Profile, интерфейс ProfileRepository и use case для чтения,
  сохранения, импорта фотографии и скачивания резюме.
- `data`: ProfileRepositoryImpl, операции с файлами на Dispatchers.IO и HTTP через OkHttp.
- `profile`: ProfileViewModel, StateFlow состояния и события навигации/открытия файла;
  Compose выполняет системные запросы разрешений и Activity Result.
- Ручной DI использует существующий AppContainer.

Preferences DataStore подходит для одного небольшого профиля с тремя строковыми полями:
сохранение атомарное, Flow автоматически обновляет экран. Room для этой структуры
не требуется. Фото копируется в files/avatars: профиль не зависит от временного
разрешения на URI галереи. Черновик и URI ожидающей камеры находятся в SavedStateHandle.
Временные фото камеры лежат в cache/camera, резюме — в files/resumes.
FileProvider предоставляет только каталоги камеры и резюме; внешний просмотрщик
получает временное право чтения. Доступ ко всему внутреннему хранилищу не открывается.
Фото ограничено 25 МБ, документ — 50 МБ. Ошибки сети, пустые файлы, неверные ссылки,
отмена выбора и отсутствие камеры/просмотрщика обрабатываются в интерфейсе.

### Разрешения и проверка разных Android

В соответствии с учебным сценарием редактор запрашивает доступ к изображениям;
при отказе закрывается. Android 7–12L (API 24–32): READ_EXTERNAL_STORAGE;
Android 13: READ_MEDIA_IMAGES; Android 14+: READ_MEDIA_IMAGES и
READ_MEDIA_VISUAL_USER_SELECTED, полный и частичный доступ считаются разрешением.
Галерея открывается системным OpenDocument с фильтром image/*.
CAMERA запрашивается при выборе камеры; отказ оставляет редактор открытым с сообщением.
Для файлов в собственных каталогах разрешение записи не нужно.

Для приложения вне учебного задания предпочтителен системный Photo Picker без
широкого разрешения на библиотеку: https://developer.android.com/training/data-storage/shared/photopicker

### Сборка и проверки

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
.\gradlew.bat :app:connectedDebugAndroidTest
```

APK: `app/build/outputs/apk/debug/app-debug.apk`.
ProfileUseCasesTest проверяет нормализацию полей и отклонение неверных ссылок
до сохранения/скачивания. ProfileFlowTest проверяет редактирование, сохранение,
обновление профиля и пересоздание Activity на подключённом Android.
Инструментальный тест меняет профиль только на тестовом устройстве.

### Результаты проверки 09.11.2026

`assembleDebug`, `testDebugUnitTest`, `lintDebug` завершились успешно.
Три новых модульных теста прошли. Lint: 0 ошибок, 20 предупреждений
(версии зависимостей, старые ресурсы и прочие рекомендации проекта).
`connectedDebugAndroidTest` прошёл на эмуляторе Android 17 / API 37:
2 теста, 0 ошибок. Новый UI-тест подтвердил редактирование, сохранение,
автоматическое обновление профиля и восстановление после пересоздания Activity.
Для успешного запуска потребовалась холодная загрузка эмулятора.
Внешние приложения камеры/галереи и загрузка реального документа этим тестом
не проверяются; видео и ручная матрица версий пока не выполнены.

### Сценарий видео для сдачи

1. Открыть «Профиль», нажать карандаш; отклонить запрос доступа и проверить возврат.
2. Снова открыть редактор и предоставить доступ (после постоянного отказа — через настройки).
3. Нажать аватарку, показать «Галерея»/«Камера», выбрать фото и проверить предпросмотр.
4. Повторить с камерой: выдать CAMERA, сделать и подтвердить снимок.
5. Ввести ФИО и прямую HTTPS-ссылку на PDF, нажать «Готово».
6. Проверить профиль и сохранение после перезапуска приложения.
7. Нажать «Резюме», дождаться скачивания и открытия PDF.

Повторить ручные проверки разрешений на API 24–32, 33 и 34+ (включая частичный
доступ), отмены выбора/съёмки, поворота экрана, отсутствия сети и просмотрщика.
Видеозапись полного сценария и проверка всех версий Android требуют отдельного прогона;
автоматические тесты не подтверждают работу внешних приложений камеры и галереи.
